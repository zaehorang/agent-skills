# mechanism-explainer

**"이게 내부적으로 어떻게 돌아가는가"를 순차적으로 따라가며 이해하는 단일 HTML 파일**을 만든다.

글로 읽으면 안 잡히는 것 — 상태가 단계마다 어떻게 바뀌는지, 어떤 데이터가 어떤 모양으로 변형되는지, 왜 이 순서여야 하는지 — 를 **눈으로 확인**하게 만드는 것이 목적이다.

## 이건 이런 게 아니다

| 아님 | 맞음 |
|---|---|
| 개념 요약 문서를 예쁘게 만든 것 | 매 단계 **상태가 실제로 바뀌는** 걸 보여주는 것 |
| 위젯·슬라이더를 늘어놓은 것 | **주의를 특정 현상으로 유도**하는 가이드된 순서 |
| 도식 한 장 | 전/후를 비교할 수 있는 **스텝 시퀀스** |
| 채팅에 띄우는 일회성 미리보기 | 프로젝트 안에 남는 **실제 .html 파일** |

## 고정된 것 · 자유로운 것

**고정 (지키지 않으면 explainer 가 아니라 예쁜 요약 문서가 된다)**
축 하나로 꿴다 · 단계마다 상태·산출물·이유가 같이 보인다 · 이름 대신 역할로 부른다 ·
용어는 그 용어가 나온 단계 안에서 푼다 · 조작에는 결과 문장이 따라붙는다 ·
**무대 위 글자가 읽히는 크기다**(2절) · 의존성 없는 단일 파일.

**자유 (내용이 정한다)**
단계 수, 레이아웃과 시각 문법(읽히는 크기만 지키면 어떻게 짜든 자유다), 어떤 조작을 심을지,
카메라를 옮길지, 움직일지 말지, 수치와 이징.
`references/patterns.md` 의 목록·표·코드는 **고르는 재료이자 출발점**이지 따라야 할 순서가 아니다.
주제가 다른 문법을 요구하면 버리고 새로 짜도 된다. 다만 거기 적힌 **함정**은 이미 값을 치르고 얻은 것이니 읽고 시작한다.

## 진행

### 0. 어디에 만들지 한 줄로 정한다

사용자가 경로를 말했으면 그것, 아니면 `explainers/<주제-슬러그>/index.html`.
**의존성 0개 · 단일 파일 · 빌드 없이 열린다.** 외부 CSS·JS·이미지를 부르지 않는다(웹폰트는 예외).

### 1. 축(spine)을 정한다 — 무엇이 단계마다 바뀌는가

이걸 못 정하면 나머지가 다 장식이 된다. 대상이 어느 유형인지 먼저 판별한다:

| 유형 | 축 | 예 |
|---|---|---|
| **파이프라인 / 변환** | 데이터의 모양 | 번들링, 컴파일, 렌더링, ETL |
| **프로토콜 / 합의** | 노드별 상태 + 오가는 메시지 | Raft, TCP 핸드셰이크, OAuth |
| **알고리즘 / 자료구조** | 메모리·포인터·컬렉션 | 정렬, 트리 회전, GC |
| **실행 / 런타임** | 콜스택·큐·힙 | 이벤트 루프, 스케줄러, async |
| **요청 수명주기** | 요청이 통과하는 레이어 | HTTP 요청, 미들웨어 체인 |

축이 정해지면 **단계를 5~9개**로 쪼갠다. 각 단계는 "이 단계가 끝나면 무엇이 이전과 달라져 있나"로 한 줄 답이 나와야 한다. 안 나오면 그건 단계가 아니라 설명이다 — 앞뒤에 합친다. 주제가 작아서 단계가 2~3개밖에 안 나오면 억지로 늘리지 않는다 — 한 화면에 조작 하나로 끝내도 된다(5절).

### 2. 무대를 주인공으로 3단 구조를 짠다

각 단계마다 세 가지가 동시에 보여야 한다. **이게 이 스킬의 핵심 패턴이다.**
세 칸의 비중은 같지 않다 — **움직이는 무대가 주인공이고 글이 옆에서 따라온다.** 반대가 되면 그림 붙은 설명 문서가 된다.

- **① 상태 다이어그램 — 지금 어디에 있나.** 단계가 바뀌어도 같은 자리에 고정하고, **새로 그리지 않는다.** 같은 SVG 의 **클래스만 갈아끼워** 상태가 변한다. 독자가 "같은 시스템의 다른 시점"으로 읽게 하는 장치.
- **② 산출물 — 뭐가 실제로 바뀌었나.** before/after 를 나란히, 바뀐 줄만 하이라이트. **진짜여야 한다** — 실제로 돌아가는 코드, 실제 로그 포맷, 실제 JSON. 지어낸 일반론은 이해를 못 만든다.
- **③ 내레이션 — 왜 이 단계가 필요한가.** "무엇을 한다"가 아니라 "없으면 뭐가 깨지나". 대안이 왜 안 되는지 한 줄이 들어가면 훨씬 오래 남는다.

**무대 크기를 먼저 계산한다.** 2컬럼에 그림을 넣으면 조용히 작아진다 — 좌표계 폭 1160 짜리 무대를 777px 컬럼에 넣으면 11.5px 라벨이 화면에서 **7.7px**가 된다. 코드도 구조도 정상이라 검증을 전부 통과하는데, 읽으라고 만든 글자가 안 읽힌다.

```
라벨 실효 px = 라벨 font-size × 카메라 배율 × (무대 렌더 폭 ÷ 무대 좌표계 폭)
```

**역할 라벨 12px · 보조로 작게 쓴 원래 이름 10px 이 하한이다.** 여기 못 미치면 설계가 틀린 것이다.
`references/examples/` 의 실측값이 기준선이다 — 역할 라벨 12.8px(넓게 보는 단계) ~ 17.2px(좁게 보는 단계), 보조 이름 10.0~10.6px.

고치는 순서:
- ⓐ **무대 컬럼을 키운다.** 무대가 가로의 **60% 이상**을 갖는다(예시는 `1.8fr : 1fr`). 읽는 글은 좁아도 되지만 무대는 아니다.
- ⓑ **카메라를 옮긴다**(아래). 넓은 그림을 한 화면에 다 넣느라 작아진 경우에 듣는다.
- ⓒ **한 단계가 켜는 구역을 줄인다.** 켜는 구역이 셋을 넘으면 그 단계가 두 가지 이야기를 하고 있다는 뜻이다 — 단계를 쪼개거나, 그 단계에서 안 쓰는 구역을 초점에서 뺀다.

**카메라는 ⓑ가 필요할 때만 쓴다.** 그림이 한 화면에 다 들어가고 글자도 읽히면 넣지 않는다 — 노드 서너 개짜리 주제에 카메라는 복잡도만 늘린다.
쓰기로 했다면: 흐리기(dim)만으로는 부족하다 — 안 볼 구역이 자리는 그대로 차지한다. 무대 내용 전체를 `<g id="cam">` 하나로 감싸고, 그 단계가 켠 구역들의 경계 상자를 화면에 꽉 차게 맞춘다. 흐려진 이웃은 가장자리에서 잘리며 "전체 중 여기"라는 맥락만 남긴다.

```js
var sc = Math.min(VW/box.w, VH/box.h, 1.95);            // 과확대 상한
var tx = VW/2 - sc*(box.x + box.w/2);
var ty = VH/2 - sc*(box.y + box.h/2);
tx = Math.min(0, Math.max(VW*(1-sc), tx));              // 지도 밖 빈 공간 금지
ty = Math.min(0, Math.max(VH*(1-sc), ty));
cam.style.transform = "translate("+tx+"px,"+ty+"px) scale("+sc+")";
```

- 클램프를 빼먹으면 지도 바깥 빈 공간이 화면의 3분의 1을 먹는다. 남는 자리는 흐려진 이웃이 채우게 둔다.
- **전체 보기 토글**을 하나 두고, 그 선택은 단계를 넘겨도 유지한다. `prefers-reduced-motion`이면 트랜지션 없이 최종 위치로.
- **화면 밖으로 나간 것을 켠 채로 두지 않는다.** 카메라가 만드는 새 실패다 — 눈으로는 안 보이고 좌표로만 잡힌다(6절).

### 3. 이름이 아니라 역할로 부른다

**독자가 모르는 이름은 아무 정보도 주지 않는다.** `main.tsx`, `AuthMiddleware`, `n_a` 같은 라벨만 있는 다이어그램은 이미 아는 사람만 읽을 수 있다.

- **다이어그램·칩·스텝 라벨은 "그게 하는 일"로 쓴다.** 진짜 이름이 필요하면 **역할을 크게, 이름을 작게** 함께 표시한다.
  - ✗ `config.ts` → ✓ **표 설정값** <sub>config.ts</sub>
  - ✗ `resolution` → ✓ **파일 찾아 나가기**
  - ✗ `n_b`, `mod_2` → 코드 안 식별자도 의미가 드러나게
- **단계 제목(`title`)은 전문용어 없이 한 문장.** 전문용어는 본문(`desc`)에서 처음 쓸 때 한 번 풀고, 그다음부터 쓴다.
- 예시 코드 안의 변수명도 마찬가지 — 생성된 코드를 보여줄 때 `a`, `mod1` 대신 `표설정_모듈`처럼 뜻이 보이게 바꿔도 된다. **정확한 재현보다 이해가 우선**이고, 그럴 땐 푸터에 "실제 구현의 이름은 다르다" 한 줄을 남긴다.

### 4. 모를 수 있는 용어는 **그 용어가 나온 단계 안에** 둔다

본문 흐름을 끊지 않으면서 막힌 사람을 구제하는 장치. **필수다.**

**위치가 핵심이다.** 페이지 최하단에 사전을 몰아두면 아무도 안 본다 — 막힌 사람은 이미 그 자리에서 멈췄고, 끝까지 스크롤해 되돌아올 만큼 동기가 남아 있지 않다. **그 용어를 처음 쓴 단계의 바로 아래**에 둔다.

- 각 단계 정의에 `terms` 목록을 달고, 그 단계 패널 아래에 `<details>` 토글로 렌더한다. 기본은 접힘 — 아는 사람은 지나가고, 막힌 사람만 편다.
- **단계당 2~4개.** 그 단계에서 **처음 등장한** 것만. 앞 단계에서 이미 푼 용어는 다시 넣지 않는다(중복은 "안 읽어도 되는 것"이라는 신호를 준다).
- 각 항목은 **한두 문장**. 정의 + "지금 이 단계에서 왜 나오는가". 사전을 옮겨 적지 않는다.
- 단계에 새 용어가 없으면 `terms`를 비운다. **칸을 채우려고 만들지 않는다.**

### 5. 따라가게 하고, 직접 해보게 한다

**진행은 가이드된 순차 진행이 기본이다** (Secret Lives of Data 방식). 자유 탐색보다 정해진 순서를 따라가게 하는 게 내부 원리 설명엔 낫다.

필수:
- **이전 / 다음** 버튼 + `←` `→` 키보드
- **스텝 레일** — 전체 몇 단계 중 어디인지, 각 단계 라벨이 보이는 상단 네비. 클릭으로 점프 가능
- **현재 / 전체** 카운트

**그리고 가능한 단계마다 조작을 하나 심는다.** 읽고 넘어간 단계와 눌러보고 결과를 본 단계는 남는 게 다르다. "이 단계가 없으면 뭐가 깨지나"를 내레이션으로 쓰는 대신 **독자가 직접 깨뜨려 보게** 만들 수 있으면 그렇게 한다.

**구현하기 전에 다섯을 한 줄씩 적어 본다** — 무엇을 누르는가 · 어떤 상태가 바뀌는가 · 화면의 어디가 달라지는가 · 결과를 어떤 문장으로 말하는가 · 어떻게 되돌리는가. 다 못 적으면 그건 장식이니 빼거나 다시 고른다.

시연 하나가 갖춰야 할 것:

- **조작은 한 단계에 하나.** 무엇을 눌러야 하는지 고민하게 만들면 이미 실패다. 버튼 라벨은 일어날 일 그대로 (`터미널 창 닫기`, `노드 2 죽이기`).
- **누르면 즉시, 눈에 띄게 달라진다.** 변화가 칩 하나 색깔뿐이면 조작이 아니라 장식이다. 그리고 **되돌릴 수 있어야** 두 번 세 번 비교한다.
- **대조가 보인다.** 있을 때 / 없을 때를 나란히 두고 **같은 조작을 양쪽에 동시에** 걸면 차이가 한 번에 읽힌다. "왜 이 구조가 필요한가"를 가장 싸게 전달하는 방법이다.
- **단계를 넘길 때 화면을 스크롤하지 않는다.** 읽던 자리가 튀면 무엇이 바뀌었는지도 같이 놓친다. 무대가 화면 밖으로 완전히 나갔을 때만 최소한으로 끌어온다.
- **움직임이 그 단계의 요점이면 `demo.auto` 로 표시하고, 도착했을 때 저절로 왕복 반복시킨다.** `auto` 를 켰으면 한 번 재생이 아니라 **반복**이어야 한다 — 한 번 재생하고 멈추면 그 순간 다른 데를 보던 사람은 영영 못 본다. **사람이 버튼을 누르면 거기서 루프를 멈추고 조작권을 넘긴다** — 내가 만지는데 화면이 혼자 계속 움직이면 조작이 아니라 방해다.
- **조작과 그 결과가 한 화면에 같이 보인다.** 버튼이 무대 아래로 밀려나면 눌러도 뭐가 바뀌었는지 안 보인다 — 무대 옆이나 바로 위로 올린다. 내레이션 끝에 붙이면 화면이 조금만 낮아져도 깨진다.
- **결과를 한 줄로 말해준다.** 조작 후 "그래서 무슨 일이 생겼나"를 문장으로 남긴다. 애니메이션만 보여주고 해석을 독자에게 떠넘기지 않는다.

**바뀐 것을 어떻게 보여줄지는 네 가지로 갈린다.**

| 보여줄 것 | 수단 |
|---|---|
| 상태가 달라졌다 | **클래스 토글** — 색·테두리·라벨. 기본값이고, 대부분 이걸로 끝난다 |
| **무엇이 어디로 갔다** | **실제로 움직인다** — 들어오고 나가는 방향, 뒤가 앞으로 당겨지는 것, 순서가 밀리는 것은 색으로 못 보여준다 |
| **계속 일어나는 중이다** | **화면을 살려 둔다** — 로그가 한 줄씩 흐르고, 커서가 깜빡이고, 알림이 떠오른다. 정지 화면은 "계속"을 못 보여준다 |
| **저것만 안 움직인다** | **움직이지 않는다** — 주변이 흐르는 동안 그대로인 것이 보여야 한다. 굶음·교착·누수가 여기 해당한다 |

움직임은 장식이 아니라 그 자체로 정보일 때만 쓴다. 판단 기준 하나: **그 움직임을 빼고 최종 화면만 봤을 때 같은 걸 알 수 있으면, 움직이지 말아야 한다.**

어느 쪽을 쓰든 공통 규칙:
- `prefers-reduced-motion`이면 **최종 상태로 즉시.** 움직임이 정보를 나르는 유일한 수단이면 안 된다.
- 흐르는 화면은 **반드시 멈출 수 있어야** 하고, 단계를 벗어나면 스스로 멈춰야 한다. 안 멈추면 뒤 단계에서 유령처럼 계속 돈다.

무엇을 조작 가능하게 만들지(대조 토글, 실패 주입, 슬라이더, 스크럽 등)는 `references/patterns.md`의 시연 레퍼토리에서 고른다.

**포맷은 고정이 아니다.** 스텝 시퀀스가 기본형이지만, 주제가 "이 둘의 차이"나 "이게 없으면 어떻게 되나" 하나로 끝나면 **한 화면 + 조작 하나**가 더 낫다. 단계 수가 아니라 축(1절)이 보이는지가 기준이다.

선택 (내용이 요구할 때만):
- 자동 재생 / 속도 조절 — 시간에 따른 반복(폴링, 이벤트 루프)이 축일 때
- **분기 시나리오** — best case 먼저, 그 다음 worst case(실패·경합·파티션). 프로토콜류엔 거의 항상 넣는다

### 6. 코드로 먼저, 그다음 눈으로

**브라우저부터 열지 않는다.** 아래는 전부 코드로 끝나고, 여기서 걸리는 게 대부분이다.

```bash
python3 <이 스킬 경로>/scripts/check_explainer.py out.html
```

한 번에 본다 — 중복 id · 대상 없는 내부 앵커 · 외부 리소스(속성과 CSS `url()` 양쪽, 웹폰트 제외) ·
남은 플레이스홀더 · `button` 아닌 것에 달린 클릭 · 타이머 정리 누락 · `prefers-reduced-motion` ·
테마 토큰 세 군데 · `body` 배경 · `<script>` 구문. `?` 로 시작하는 줄은 확인 권고이고 종료 코드에 영향을 주지 않는다.
**통과할 때까지 브라우저를 열지 않는다.**

본문에 거는 인용 하이퍼링크(`<a href="https://…">`)는 의존성이 아니다 — 막는 것은 **리소스를 부르는 것**뿐이다.

**그다음 눈으로만 판단되는 것**을 브라우저에서 본다. 스크린샷은 장당 비용이 붙으니 필요한 장면만.

- **모든 단계를 한 번씩** 넘겨본다 — 콘솔 에러 0, body에 가로 스크롤 없음, 단계 전환에 스크롤이 안 튐. 이 셋은 한 번의 스크립트 실행으로 같이 잰다.
- **크기** — 노드 라벨이 화면에서 **12px 이상**인지. 무대 렌더 폭을 재서 2절 식에 넣는다. 눈으로 "작아 보인다"는 판단이 서면 이미 늦었다고 보고 수치를 잰다.
- **잘림** — 켜둔(활성·완료) 연결선과 라벨이 전부 보이는 영역 안에 있는지. 카메라를 썼다면 반드시 잰다:

```js
// 보이는 영역(사용자 좌표) 대 각 요소의 bbox — 걸린 것만 나온다
var m = /translate\(([-\d.]+)px,\s*([-\d.]+)px\)\s*scale\(([\d.]+)\)/.exec(cam.style.transform);
var tx=+m[1], ty=+m[2], k=+m[3], v={x0:-tx/k, y0:-ty/k, x1:(VW-tx)/k, y1:(VH-ty)/k};
[].filter.call(document.querySelectorAll('#edges *'), function(el){
  if ((el.getAttribute('class')||'').indexOf('off') >= 0) return false;
  var b = el.getBBox();
  return b.x < v.x0 || b.y < v.y0 || b.x+b.width > v.x1 || b.y+b.height > v.y1;
}).map(function(el){ return el.id; });   // [] 여야 한다
```

- **라벨** — 다이어그램과 스텝 레일에 뜻 없는 이름만 남은 곳이 없는지.
- **용어** — 전문용어가 처음 나온 그 단계에 뜻이 같이 있는지.
- **조작** — 눌러서 실제로 바뀌는지, 되돌아오는지, 결과 문장이 따라붙는지, `auto` 를 켠 시연이 **반복**되는지.
- **움직임** — 나가는 것이 화면 안에서 보이게 나가는지, 라벨을 뚫지 않는지, 단계를 옮기면 제자리로 돌아오는지.
- **되돌리기** — 되돌린 뒤 상태가 **진입 직후와 완전히 같은지**. 흐림 클래스, 죽은 채 남은 칸, 켜진 채 잊힌 선이 자주 남는다.
- 라이트/다크 양쪽.

**접근성은 세 줄로 끝난다** — 이것만 지키면 나머지는 평범한 HTML 이 해 준다.
- 판정 문장 자리에 `aria-live="polite"`. 조작 결과가 화면을 못 보는 사람에게 닿는 유일한 통로다.
- 토글 버튼에 `aria-pressed`. 되돌릴 수 있다는 사실이 라벨 말고도 전달된다.
- **모든 조작은 실제 `<button>`으로.** 클릭 핸들러를 `div`나 SVG 도형에 달면 키보드로 닿지 않는다.

애니메이션 **중간** 프레임은 자동으로 잡기 어렵다 — 백그라운드 탭은 `requestAnimationFrame`이 멈춰 트랜지션이 진행되지 않고, 스크린샷은 도구 왕복 때문에 대개 끝난 뒤에 찍힌다. ① 최종 상태는 스크린샷으로 ② 중간 동작은 `element.style` 값을 코드로 읽어서 ③ 모양이 궁금하면 transition 지속을 잠깐 몇 초로 늘려 한 프레임 고정해서 본다.

**보고에 쓴 문장은 전부 방금 확인한 것이어야 한다.** 만들어 둔 기능을 확인 없이 "된다"고 쓰지 않는다 — 시간이 없어 못 본 것은 못 봤다고 쓴다. 구현했다고 믿은 것과 실제로 동작하는 것은 자주 다르다.

## 페이지를 짤 때

한 파일에 `<style>` + 마크업 + `<script>`. 구조는 **단계 배열 하나와 그걸 그리는 함수 하나**면 끝난다.

```js
var STEPS = [{
  nav:"번들",                                  // 스텝 레일에 뜨는 2~5자
  title:"이 단계가 끝나면 뭐가 달라져 있나",      // 전문용어 없이 한 문장
  desc:"<p>왜 이 단계가 필요한가</p>",
  graph:{ focus:["r_build"],                    // 이 단계에 카메라를 맞출 구역
          done:["n_a"], active:["n_b"], idle:["n_c"], edges:{ e_a_b:"active" } },
  panels:"…before/after 코드·로그 HTML…",
  terms:[{ ko:"번들", en:"bundle", def:"…" }],  // 이 단계에서 처음 나온 것만
  enter:fillIn,                                 // (선택) 도착하면 한 번 움직일 것
  demo:{ auto:true, label:"캐시 비우기", labelOn:"되돌리기",   // labelOn 이 곧 reset
         hint:"무엇을 보라는 한 줄",
         run:function(on){ /* 상태만 바꾸고 render 를 부른다 */ return "판정 문장"; } }
}];
```

`go(n)` 하나가 단계를 그린다 — 기준 상태로 리셋 → 텍스트 교체 → 그래프 클래스 적용 → 카메라 이동 → `enter` → 시연 버튼 렌더. 이전/다음 버튼과 `←` `→` 키가 `go`를 부른다.

**직접 짜면 틀리기 쉬운 여덟 가지** (전부 값을 치르고 얻은 것)

1. **다이어그램은 다시 그리지 않는다.** 같은 SVG의 클래스만 교체한다 — `el.classList.remove.apply(el.classList, STATES); el.classList.add(s)`. 상태는 4~5종까지, 색만으로 구분하지 말고 테두리·라벨을 같이 쓴다.
2. **인라인 `transform` 은 기존 배치를 통째로 덮는다.** 밀어낼 값만 쓰면 원래 자리가 지워진다. 제자리 좌표를 따로 들고 있다가 **원래 배치 + 밀어낼 값**을 합쳐서 쓴다. SVG가 특히 잘 물린다 — `transform="translate(x,y)"` 속성이 CSS에 덮이므로 `translate(x, y+dy)`로 x까지 같이 써야 하고, 빼먹으면 요소가 왼쪽 끝으로 튄다.
3. **시작 위치 → 강제 리플로우 → 목표 위치.** 사이에 `void document.documentElement.offsetWidth`가 없으면 애니메이션 없이 순간이동한다.
4. **타이머는 한 배열에 등록하고 한 번에 정리한다.** `setInterval`뿐 아니라 `setTimeout`도. 단계 전환·토글마다 비운다.
5. **테마 토큰은 세 군데에 쓴다.** `:root`(라이트) · `@media (prefers-color-scheme:dark){ :root:not([data-theme="light"]) }` · `:root[data-theme="dark"]`. `body` 배경을 토큰으로 명시하지 않으면 뷰어 배경이 비친다.
6. **`go`는 스크롤을 건드리지 않는다.** 무대가 화면 밖으로 완전히 나갔을 때만 최소한으로 끌어온다.
7. **기준 상태를 만드는 함수를 하나 둔다.** 단계 진입도, 시연의 되돌리기도 **반드시 그 함수를 거친다.** 상태를 객체 하나로 모으고 `render(state)` 로 그리는 방식도 좋고, 기준 상태로 리셋한 뒤 그 단계의 차이만 얹는 방식도 좋다 — 갈리는 지점은 그게 아니라 **되돌아갈 곳이 한 군데로 정의돼 있는가**다.
8. **그래서 되돌리기는 부분 복구가 아니다.** "켠 것만 다시 끈다"로 짜면 반드시 새는 게 남는다 — 흐림 클래스, 죽은 채 남은 칸, 켜진 채 화면 밖으로 나간 선. 시연의 `run(false)` 가 손으로 서너 줄 원복하고 있으면 그게 신호다.

타이밍 기본값은 `references/patterns.md` 의 표에서 가져다 쓴다.

더 필요하면 `references/patterns.md` — 유형별 시각 문법, 시연 레퍼토리, 움직임·살아 있는 화면 만드는 법, 흔한 실패. **통으로 읽지 말고 해당 유형 절과 쓰기로 한 장치 절만 편다.**

막히면 `references/examples/container-orchestration.html` 이 검증까지 끝낸 완성본이다 — 9단계, 단계별 카메라, 단계마다 조작 하나, 흐르는 로그. **읽지 말고 브라우저로 열어 본 다음** 필요한 부분만 찾아 본다.

## 판단이 설 때 돌아올 두 문장

1. **Do & Show & Tell** — 추상 개념은 글로, 시간에 따른 변화는 애니메이션으로, 프로세스·시스템은 인터랙션으로. 하나로 다 하려 들지 않는다. *(Nicky Case)*
2. **주의를 유도한다** — 위젯을 늘어놓는 것과 explorable explanation 의 차이는, 후자가 **독자가 무엇을 봐야 하는지 의도적으로 안내**한다는 것. *(Bret Victor)*
