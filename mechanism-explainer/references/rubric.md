# 평가 rubric — 만든 explainer 가 "잘 만들어졌는가"

세 겹으로 본다. **A·B 는 기계가 판정하고, C 는 사람이나 모델이 판정한다.** A → B → C 순서로, 앞 겹을 통과해야 다음으로 간다.

## A. 정적 검사 — 통과/실패

```bash
python3 <스킬>/scripts/check_explainer.py <파일.html>
```

`FAIL` 이 0건이어야 한다. `?` 경고(내레이션 길이 · aria · TODO 잔존)는 보고에 옮겨 적는다.

## B. 브라우저 자동 검사 — 숫자로 판정

1. 파일이 있는 폴더를 로컬 서버로 연다(`python3 -m http.server <포트>`). **다시 열 때는 포트를 바꾼다** — 같은 포트면 예전 파일이 캐시에서 읽힌다.
2. 콘솔 에러를 자동화 도구로 읽는다(페이지를 연 직후의 에러는 아래 스크립트가 못 잡는다).
3. `scripts/verify_browser.js` 내용을 페이지에서 실행하고 `await MEV.all()` 의 `summary` 를 본다.
   스킬 폴더를 서버 루트로 열었다면 `(0,eval)(await (await fetch('/scripts/verify_browser.js')).text()); await MEV.all()`.
   다른 폴더를 루트로 열었다면 파일 내용 전체를 JS 실행에 붙여 넣고 끝에 `await MEV.all()` 을 둔다.
   **단계가 많으면(6개 이상) 도구 호출 45초 제한에 걸린다** — `window.__r = null; MEV.all().then(r => window.__r = r)` 로 띄워 두고 `window.__r` 을 나중에 읽는다. 자동화 탭이 백그라운드면 타이머가 1초 단위로 뭉쳐 9단계에 2분쯤 걸린다.

| 항목 | 뜻 | 통과 기준 |
|---|---|---|
| B1 `errors` | 검사 중 JS 에러 | 0 (+ 2단계 콘솔 에러 0) |
| B2 `hscroll` | body 에 가로 스크롤이 생긴 단계 | 없음 |
| B3 `scrollJump` | 단계 전환에 스크롤 위치가 튄 단계 | 없음 |
| B4 `labelBelow` | 역할 라벨(`.nd .t1`) 실효 크기가 12px 미만인 단계 | 없음 |
| B5 `subBelow` | 보조 이름(`.nd .t2`) 실효 크기가 10px 미만인 단계 | 없음 |
| B6 `clipped` | 켜둔 노드·선이 무대 보이는 영역 밖으로 나간 단계 | 없음 |
| B7 `demoNoChange` | 시연 버튼을 눌렀는데 판정 문장이 안 바뀐 단계 | 없음 |
| B8 `pressedMissing` | 시연 버튼에 `aria-pressed` 가 없는 단계 | 없음 |
| B9 `restoreMismatch` | 되돌린 뒤 무대 상태 ≠ 진입 직후 상태 | 없음 |
| B10 `autoKeepsRunning` | `auto` 시연이 사람이 누른 뒤에도 혼자 바뀜 | 없음 |
| B11 `ariaLiveMissing` | 시연이 있는데 판정 자리에 `aria-live` 가 없음 | 없음 |
| B12 `themeUnchanged` | `data-theme="dark"` 로 바꿔도 body 배경이 그대로 | false |

`warns` 는 경고다 — `drifting`(시연 없는 단계인데 무대가 혼자 바뀜: 살아 있는 화면이면 정상) · `stepsWithoutDemo`(조작이 없는 단계 목록 — 5절 "가능한 단계마다 조작 하나").

`summary.pass` 가 true 여야 C 로 간다.

### 화면 크기 — 두 크기에서 잰다

라벨 실효 px 는 무대 렌더 폭에 비례한다. **넓은 창(가로 ≥ 1400)과 좁은 창(가로 ≈ 1100, 2컬럼이 유지되는 최소)** 에서 잰다. 창을 못 바꾸면 한 크기만 쟀다는 사실과 그 크기(`summary.viewport`·`stageW`)를 보고에 쓴다 — "pass" 만 쓰고 크기를 빼지 않는다. 1060px 아래는 1컬럼으로 접히므로 범위 밖이다.

## C. 품질 — 항목마다 0·1·2점

explainer 를 직접 열어 단계를 끝까지 넘기고 조작을 눌러 본 뒤 매긴다. 근거(어느 단계·어느 칸)를 한 줄씩 남긴다.

| # | 항목 | 2점 | 1점 | 0점 |
|---|---|---|---|---|
| C1 | **축이 보인다** | 모든 단계가 "이 단계가 끝나면 무엇이 달라졌나"에 한 줄로 답하고, 같은 다이어그램의 상태만 바뀐다 | 한두 단계가 설명이지 단계가 아니다 | 단계마다 그림을 새로 그리거나 축이 없다 |
| C2 | **산출물이 진짜다** | 코드·로그·페이로드가 실제 형식이고 바뀐 줄만 하이라이트된다 | 형식은 맞으나 일반론 값(`foo`, `Component A`)이 섞였다 | 지어낸 형식이거나 산출물 칸이 비었다 |
| C3 | **역할로 부른다** | 다이어그램·레일 라벨이 역할이고, 지어낸 비유 어휘가 1단계 대조표에 빠짐없이 있다 | 역할 라벨이나 대조표 중 하나가 샜다 | 이름만 있는 라벨이 대부분이다 |
| C4 | **조작이 정보다** | 단계마다 조작 하나, 누르면 눈에 띄게 바뀌고, 결과 문장이 따라붙는다 | 조작이 있으나 변화가 미미하거나 결과 문장이 없다 | 조작이 없거나 장식이다 |
| C5 | **내레이션이 무대를 밀어내지 않는다** | 리드 한 줄 + 불렛 2~4, 마지막 불렛이 "없으면 뭐가 깨지나", 단계당 280자 안팎 | 분량은 맞으나 "없으면"이 빠졌거나 그 반대 | 줄글이 길어 무대보다 글을 읽게 된다 |
| C6 | **용어가 제자리에 있다** | 전문용어가 처음 나온 단계 안에서 풀리고 정식 명칭이 본문에 병기된다 | 일부 용어가 토글에만 있거나 다음 단계에서 풀린다 | 사전이 끝에 몰려 있거나 없다 |
| C7 | **움직임이 정보다** | 움직인 것만 움직이고, 최종 화면만 봐도 같은 걸 알 수 있는 움직임은 없다 | 장식 움직임이 한두 군데 있다 | 움직임이 요점과 무관하거나 움직임 없이는 이해가 안 된다 |

**합격: 14점 중 11점 이상, 0점 항목 없음.**

## 보고 형식

```markdown
# 평가: <주제> (<파일>) · <날짜> · viewport <가로x세로> · stageW <px>

B: pass @1512x828 (stageW 935) — B4 12.2px · B5 10.3px · warns: stepsWithoutDemo [1,3]
   (크기별로 한 줄씩. 한 크기만 쟀으면 "한 크기만 잼: 이유")
C: C1 2 · C2 2 · C3 1 · C4 2 · C5 2 · C6 2 · C7 2 = 13/14 → 합격
근거
- C3 1점: 4단계 본문의 "명단"이 1단계 대조표에 없다
고칠 것 (중요한 순서)
1. …
스킬(SKILL.md·references·template)에 반영할 것 — 만드는 사람이 막혔거나 놓친 지점
- …
```
