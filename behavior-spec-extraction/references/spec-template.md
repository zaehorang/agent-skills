# 기능 명세 템플릿

명세 하나는 "사용자 눈에 하나로 보이는 동작" 하나를 다룬다. 아래 6섹션은 순서와 이름을 바꾸지 않는다. 린터가 이 이름으로 섹션을 찾는다.

## 템플릿

```
# <기능 이름 — 사용자가 부르는 말로>

## Goal
한 문장. 이 기능이 사용자에게 무엇을 해주는가.

## Triggers
어떤 사용자 행동 / 외부 이벤트 / 시간 조건이 이 기능을 발동시키는가.

## Inputs
외부에서 받는 상태·데이터. 각 항목마다 "누가 정하는가"를 함께 적는다.

## Outputs
화면 / 저장된 데이터 / 서버에 만드는 변화.

## Edge cases
정상 경로에서 벗어났을 때 무엇이 일어나는가. 입력이 비었을 때, 네트워크가 끊겼을 때,
같은 조작이 연달아 들어왔을 때, 한글 입력 중일 때, 브라우저·기기가 다를 때.

## Acceptance
"<조건>에서 <행동>하면 <관측되는 결과>가 된다" 형태의 목록.
한 항목은 한 가지만 검증한다.

## 열린 질문
코드만으로는 알 수 없어 사람에게 확인해야 하는 것. 질문 형태로 쓴다.
```

`열린 질문`은 확인이 끝나면 지운다. 나머지 6섹션은 비어 있어도 지우지 않고 "없음"이라고 적는다 — 없다는 사실 자체가 검수 대상이다.

## 섹션별 작성 규칙

### Goal
- **한 문장.** 두 문장이 필요하면 기능을 잘못 잘랐다는 신호다.
- 무엇을 하는지가 아니라 **사용자에게 무엇이 좋아지는지**를 쓴다.
- 나쁨: "입력값을 검증하고 서버에 전송한다"
- 좋음: "사용자가 잘못 적은 값을 보내기 전에 알려주어, 실패한 제출로 시간을 버리지 않게 한다"

### Triggers
- 사람의 행동인지 시스템의 조건인지 구분해서 적는다.
- "언제부터 이 기능이 반응하기 시작하는지"도 계기다. 화면이 열린 직후부터인지, 사용자가 한 번 만진 뒤부터인지.
- 나쁨: "화면 로드 시" / 좋음: "사용자가 이 화면을 열어 목록이 보이기 시작한 순간부터"

### Inputs
- 각 항목에 **누가 그 값을 정하는가**를 붙인다: 사용자가 입력, 이전 화면에서 넘어옴, 서버가 내려줌, 설치할 때 정해짐.
- 값의 범위·필수 여부·기본값 중 관측 가능한 것만 적는다.
- 나쁨: "설정 객체" / 좋음: "한 번에 보여줄 개수 — 사용자가 설정 화면에서 정하고, 정하지 않으면 20개"

### Outputs
- 세 곳으로 나눠 생각한다: 화면에 보이는 것 / 다음에 열어도 남아 있는 것 / 다른 사람·다른 기기에서 보이게 되는 것.
- "저장한다"로 끝내지 말고 **언제까지 남는지**를 적는다.

### Edge cases
- 최소한 이 넷은 매번 검토한다: 값이 비었거나 예상 밖일 때 / 연결이 끊기거나 느릴 때 / 같은 조작이 두 번 이상 겹칠 때 / 사용 환경이 다를 때(기기, 브라우저, 입력기, 언어).
- 각 항목은 "무엇이 일어나는가"까지 쓴다. "예외 처리한다"는 명세가 아니다.
- 좋음: "전송 중 연결이 끊기면 사용자가 쓴 내용은 화면에 그대로 남고, 다시 시도할 수 있다는 안내가 보인다"

### Acceptance
- 형태: **"<조건>에서 <행동>하면 <관측되는 결과>가 된다."**
- 한 항목 = 한 검증. "그리고"로 두 결과를 잇지 않는다. 나누면 두 항목이다.
- 사람이 화면만 보고 판단할 수 있어야 한다. 코드를 열거나 로그를 봐야 하면 Acceptance가 아니라 Outputs의 서술이다.
- 나쁨: "정상 동작한다" / "상태가 올바르게 갱신된다"
- 좋음: "목록이 비어 있는 상태에서 새 항목을 추가하면, 추가한 항목이 목록 맨 위에 보인다"
- 좋음: "전송이 실패한 뒤 화면을 다시 열면, 쓰던 내용이 그대로 남아 있다"

## 좋은 예 / 나쁜 예 대조

| 나쁨 (구현 누출) | 좋음 (관측 가능한 동작) |
|---|---|
| 마운트 시 초기화한다 | 화면이 열리면 목록을 처음부터 다시 불러와 보여준다 |
| 매 프레임 상태를 확인한다 | 값이 바뀌면 사용자가 끊김을 느끼지 못할 만큼 즉시 화면에 반영된다 |
| 전역 매니저가 세션을 들고 있다 | 로그인 상태는 화면을 옮겨 다녀도 유지되고, 앱을 완전히 껐다 켜도 남아 있다 |
| 비동기로 처리한다 | 저장은 즉시 끝나지 않는다. 그동안 버튼은 다시 누를 수 없고 진행 중임이 보인다 |
| 외부에서 주입된 설정을 사용한다 | 표시 개수는 설정 화면에서 사용자가 정하고, 정하지 않으면 20개다 |
| 예외를 잡아 처리한다 | 서버가 응답하지 않으면 "잠시 후 다시 시도해 주세요"라는 안내가 보이고, 쓴 내용은 사라지지 않는다 |
| 결과를 캐싱한다 | (사용자가 체감하지 못하면 삭제) 또는 같은 항목을 다시 열면 기다림 없이 바로 보인다 |
| 목록을 정렬해 렌더링한다 | 목록은 최근에 바뀐 것이 위에 온다 |
