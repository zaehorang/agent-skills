# 구현 패턴 → 명세 표현 번역 규칙

기술과 무관한 규칙 7개가 본체다. 아래 언어·프레임워크별 표는 그 규칙이 실제 코드에서 어떻게 생겼는지 알아보게 하는 예시일 뿐이며, 목록에 없는 기술도 같은 규칙으로 번역한다.

번역할 때 매번 던지는 질문은 하나다: **"밖에서 관측되는 것이 무엇인가."** 답이 "없음"이면 그 코드는 명세에 쓰지 않는다.

## 규칙 1 — 생명주기 훅은 "언제부터 반응하는가"로 바꾼다

초기화·마운트·진입 훅은 그 자체로는 사용자에게 보이지 않는다. 보이는 것은 "언제부터 이 화면이 반응하기 시작하고, 그 순간 무엇이 이미 채워져 있는가"다.

- 나쁨: "마운트 시 데이터를 불러온다"
- 좋음: "화면을 열면 목록을 불러오는 동안 빈 자리 표시가 보이고, 다 불러오면 항목으로 바뀐다"

## 규칙 2 — 폴링·타이머·구독은 "무엇이 얼마나 빨리 반영되는가"로 바꾼다

매 프레임 확인인지, 3초마다인지, 서버가 밀어주는지는 구현이다. 관측되는 것은 **반영 지연**과 **누가 먼저 움직이는가**다.

- 나쁨: "매 프레임 위치를 확인한다"
- 좋음: "값이 바뀌면 사용자가 끊김을 느끼지 못할 만큼 즉시 화면에 반영된다"
- 좋음: "다른 사람이 바꾼 내용은 최대 몇 초 안에 내 화면에도 나타난다. 새로 고침은 필요 없다"

주기가 사용자에게 실제로 체감되는 경우(예: 30초마다 갱신)에는 그 숫자를 남긴다. 체감되지 않으면 지운다.

## 규칙 3 — 전역 싱글턴·매니저·스토어는 "어디까지 유지되는 상태"로 바꾼다

관측되는 것은 상태의 **수명 범위**다. 화면을 옮기면 사라지는가, 앱을 껐다 켜도 남는가, 다른 기기에서도 보이는가.

- 나쁨: "세션 매니저가 로그인 정보를 보관한다"
- 좋음: "로그인 상태는 화면을 옮겨도 유지되고, 앱을 껐다 켜도 남는다. 다른 기기에서는 다시 로그인해야 한다"

## 규칙 4 — 비동기 원시(코루틴·프라미스·백그라운드 작업)는 "기다리는 동안 보이는 것"으로 바꾼다

관측되는 것은 세 가지다: 즉시 끝나지 않는다는 사실, 기다리는 동안 사용자가 무엇을 볼 수 있고 무엇을 못 하는지, 끝났을 때 무엇이 바뀌는지.

- 나쁨: "저장을 비동기로 처리한다"
- 좋음: "저장은 즉시 끝나지 않는다. 진행 중에는 저장 버튼을 다시 누를 수 없고, 끝나면 저장된 시각이 표시된다"

취소 가능 여부, 화면을 떠나면 어떻게 되는지도 관측 대상이다.

## 규칙 5 — 주입된 의존성·설정값은 "누가 정하는 값인가"로 바꾼다

Inputs 섹션의 핵심이다. 값 자체보다 **결정 주체**가 검수 포인트다: 사용자가 정하는가, 관리자가 정하는가, 설치할 때 고정되는가, 서버가 내려주는가.

- 나쁨: "설정 객체를 외부에서 주입받는다"
- 좋음: "한 번에 보여줄 개수는 사용자가 설정 화면에서 정한다. 정하지 않으면 20개다"

## 규칙 6 — 예외·에러 타입은 "실패했을 때 사용자가 겪는 일"로 바꾼다

에러 코드나 예외 이름은 명세에 쓰지 않는다. 대신 사용자가 보는 안내, 그 시점에 잃는 것과 남는 것, 다시 시도할 수 있는지를 쓴다.

- 나쁨: "네트워크 예외를 잡아 처리한다"
- 좋음: "전송 중 연결이 끊기면 쓰던 내용은 화면에 그대로 남고, 다시 시도할 수 있다는 안내가 보인다"

사용자에게 보이는 문구가 정해져 있으면 그 문구는 그대로 인용한다 — 그것은 구현이 아니라 관측 대상이다.

## 규칙 7 — 관측되지 않는 것은 삭제한다

내부 캐시, 메모이제이션, 자료구조 선택, 파일 분리, 리팩터링 흔적은 기본적으로 명세에 없다. 예외는 **사용자가 체감하는 결과가 있을 때**뿐이고, 그때도 원인이 아니라 결과를 쓴다.

- 삭제: "결과를 메모리에 캐싱해 재계산을 피한다"
- 남김(체감될 때): "한 번 연 항목을 다시 열면 기다림 없이 바로 보인다"

## 예시표

### Unity / 게임 엔진

| 구현 패턴 | 명세에 쓸 표현 |
|---|---|
| 초기화·시작 생명주기 훅 | "화면(또는 오브젝트)이 등장한 시점부터" — 그때 이미 채워져 있는 것을 함께 |
| 매 프레임 갱신 루프 | 실제로 어떤 상태를 어느 빈도로 반영하는지 풀어서. 체감되지 않으면 "즉시" |
| 전역 인스턴스 매니저 | "전역 상태" 또는 도메인별로 나눠 "무엇이 어디까지 유지되는지" |
| 지연 실행·프레임 대기 | "즉시 끝나지 않는 작업", "잠시 뒤에 일어나는 일" |
| 인스펙터로 주입되는 값 | "외부에서 정해지는 값" + 누가 정하는지(기획 데이터/빌드 시점/사용자) |
| 물리·충돌 콜백 | "두 대상이 닿으면" 같은 사용자가 보는 사건 |
| 씬 전환 | "화면이 바뀌면" + 그때 유지되는 것과 사라지는 것 |

### 웹 프런트엔드

| 구현 패턴 | 명세에 쓸 표현 |
|---|---|
| 마운트 시 부수 효과 | "화면이 열리면" + 그동안 보이는 것 |
| 상태 훅·스토어 | "화면이 기억하는 값" / "화면을 옮겨도 유지되는 값" |
| 전역 스토어·컨텍스트 | "여러 화면이 함께 보는 상태" |
| 디바운스·스로틀 | "입력을 멈춘 뒤 잠깐 있다가 결과가 갱신된다" |
| 낙관적 갱신 | "누른 즉시 화면에 반영되고, 서버가 거절하면 되돌아가며 안내가 보인다" |
| 조합 입력 처리 | "한글처럼 조합해서 쓰는 입력은 글자가 완성되기 전에는 검색이 시작되지 않는다" |

### 모바일 (iOS / Android)

| 구현 패턴 | 명세에 쓸 표현 |
|---|---|
| 화면 진입 생명주기 | "화면이 보이기 시작하면" — 처음 열 때와 뒤로 돌아왔을 때를 구분해서 |
| 백그라운드 진입·복귀 | "앱을 내렸다 다시 열면" + 남는 것과 새로 불러오는 것 |
| 권한 요청 | "처음 이 기능을 쓸 때 허용을 묻고, 거절하면 무엇이 안 되는지" |
| 로컬 저장소 | "앱을 껐다 켜도 남는다" / "앱을 지우면 사라진다" |
| 푸시 알림 | "앱을 보고 있지 않아도 알림이 온다" + 눌렀을 때 열리는 화면 |

| 구현 패턴 | 명세에 쓸 표현 |
|---|---|
| 트랜잭션 | "중간에 실패하면 아무것도 반영되지 않는다" |

| 인증 미들웨어 | "로그인하지 않은 사람은 이 동작을 할 수 없고, 대신 무엇을 보게 되는지" |
| 레이트 리밋 | "짧은 시간에 너무 많이 요청하면 잠시 막히고, 언제 풀리는지 안내된다" |
