# 노트 형식

파일명: `reviews/YYYY-MM-DD-회사-키워드.md`
예) `2026-03-14-acme-websocket-chat.md` — 날짜, 회사 슬러그, 글의 핵심 키워드. 전부 영문 케밥.

## Frontmatter

```yaml
---
date: YYYY-MM-DD
company: 회사 (작성자)
source: 원문 링크
tags: [도메인, 문제패턴]          # 아래 어휘에서 2~4개
raw: ../raw/YYYY-MM-DD-회사-키워드.jsonl
---
```

## 필수 섹션 — 매번. 이게 노트의 뼈대다

| 섹션 | 목적 |
|---|---|
| `# 제목` | |
| `## 🔑 한 줄 요약` | 나중에 **이 줄만 훑어도 떠오르게**. 인용구(`>`)로 |
| `## 📌 무슨 글` | 중립·짧게 (3줄 내외) |
| `## 🧠 내가 이해한 것 → 교정` | **핵심 섹션.** 내 생각 → ✅ / 🔧 / 💡 |
| `## 🔁 도메인 안 가리는 패턴` | 전이 가능한 일반 규칙 — **사고 자산의 핵심** |
| `## 🎯 오늘 챙길 한 줄` | 규칙 / 휴리스틱 / 질문 형태 |

## 옵션 섹션 — 그날 진짜 있을 때만

**칸을 채우려고 만들지 않는다.**

| 섹션 | 넣을 때 |
|---|---|
| `## ❓ 궁금증 → 해소` | **글 맥락 질문만.** 범용 개념 질문은 `concepts/`로 |
| `## ⚖️ 비교표` | 대안 설계가 실제로 있을 때 |
| `## 🐛 겪은 문제 & 해결` | 글에 사건이 있을 때 |
| `## 🛠️ 직접 만들어본 것` | 실습·시각화를 만들었을 때 |
| `## 📚 이 글로 정리한 개념` | 개념을 `concepts/`로 뺐을 때 — 링크 + 왜 중요한지 한 줄 |

> `🔮 미해결/다음에 팔 것` 섹션은 두지 않는다. 안 닫힌 질문·실습거리는 `QUESTIONS.md` / `TRY.md`로 뺀다.

## 🧠 섹션 쓰는 법

사용자가 실제로 한 말을 **먼저 적고**, 그 아래 교정을 붙인다. 순서가 반대면 "내가 뭘 잘못 알았는지"가 안 남는다.

```markdown
**① 웹소켓을 왜 쓰나**
- 내 생각: HTTP는 매번 인증/연결하니, 한 번 인증하고 통로 열어 비용 절감.
- 🔧 교정: 두 군데가 틀렸다 → [WebSocket](../concepts/websocket.md).
  (a) TCP "대신"이 아니라 **TCP "위에서"** 돈다.
  (b) 1순위 이유는 인증 절감이 아니라 **server push**. 인증 절감은 부차적.
```

사용자가 스스로 도달한 것도 남긴다 — `**④ "여기서 말하는 알림 = 이벤트 알림?"** → 맞음. (스스로 도달)`

## 🔁 패턴 쓰는 법

**도메인 단어를 빼고** 쓴다. "웹소켓은…"이 아니라 "실시간 기능은…", 더 좋게는 "상태를 나르는 채널은…".

같은 모양의 패턴이 이전 노트에 있으면 그 자리에서 링크한다.

## 태그

**어휘는 이 스킬이 정하지 않는다.** 무엇을 읽는 사람이냐에 따라 필요한 태그가 다르고, 어휘는 쓰면서 자란다. 개인 어휘를 늘리려고 공유 스킬을 고치는 일이 생기면 안 된다.

- **프로젝트에 어휘 목록이 있으면 거기서만 고른다.** 없는 태그를 지어내지 않는다.
- 목록에 없는데 꼭 필요하면 사용자에게 확인하고 **프로젝트 목록에 추가**한다.
- 어휘 목록 자체가 없으면 처음 한 번 만들어 프로젝트에 둔다.
- 노트당 **2~4개**. 많으면 인출이 안 된다.

두 축으로 나누면 관리가 쉽다 — **도메인**(`backend` `ios` `ml` …)과 **문제 패턴**(`성능` `마이그레이션` `장애대응` …). 도메인만 있으면 "비슷한 문제"로 못 찾고, 패턴만 있으면 "그 분야"로 못 찾는다.
