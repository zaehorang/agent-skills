# explorable-world

부품이 여럿이고 **"누가 누구에게 무엇을 말하나"**가 핵심인 주제를 **탐험하는 지도**로 만든다.
보는 사람은 살아 움직이는 세계를 먼저 보고, 사건을 일으켜 흐름을 따라가고, 궁금한 만큼만 깊이 들어간다.

완성 예시: `examples/k8s-harbor/` (쿠버네티스 = 항구, 사건 "앱 배포하기" 7장면). 막히면 이것을 열어 본다.

## 이건 이런 게 아니다

| 아님 | 맞음 |
|---|---|
| 네모 칸과 화살표 도식 | 장소·인물·물건이 있는 **세계** (아이소메트릭 지도) |
| 처음부터 설명을 다 보여주는 문서 | 늘 보이는 **자막 한두 줄**, 나머지는 궁금할 때 열기 |
| 비유만 있는 동화 | 비유 옆에 **실제 이름**, 깊이 들어가면 **실제 요청·기록·출력** |
| 순서대로 넘기는 슬라이드 | 사건을 **일으키고**, 아무 물체나 **눌러 보는** 탐험 |
| 부품 하나를 열어 그 안의 상태 변형을 깊이 따라가는 것 | **부품 전부를 한 지도에** 펴놓고 누가 누구에게 보내는지 보는 것 |

## 맞는 주제 · 안 맞는 주제

**전체를 보고** 싶을 때 쓴다. 기준은 "이 사건이 일어나면 누가 누구에게 무엇을 보내나"가 핵심이고, 부품을 전부 한 지도에 올려야 이해되는가다. 부품은 많고(대개 6개 이상) 각 부품의 내부는 얕다. 증거는 부품 사이를 오가는 요청과 그 순간의 실제 명령 출력이다.

| 맞는다 | 안 맞는다 (다른 도구) |
|---|---|
| 쿠버네티스 컨트롤 플레인 (항구) · 마이크로서비스 주문 처리 (시장 거리) · CI/CD (공장 라인) | 퀵소트·B-tree·GC 처럼 메모리 칸이 바뀌는 알고리즘 (단일 메커니즘) |
| 메시지 큐 (택배 허브) · 브라우저가 페이지를 받기까지 DNS·CDN·LB·서버 (우편 도시) | 번들링·컴파일·렌더링처럼 데이터의 모양이 단계마다 변하는 파이프라인 |
| OAuth 네 주체 (놀이공원) · 데이터 파이프라인 (상수도) · DNS 계층 질의 (안내소 체인) · 깃 협업 (출판사) | 이벤트 루프·async 처럼 콜스택·큐 하나의 내용물을 따라가는 런타임 |
| | REST 와 GraphQL 비교처럼 소통 지형이 없는 개념 비교 (글·표) · 설치법 같은 사용법 |

같은 이름이라도 **부품들을 전부 지도에 펴놓으면** 이 스킬이다 — TLS 라면 브라우저·CA·OCSP·서버가 인증서를 주고받는 지형, OAuth 라면 네 주체가 리다이렉트로 서로를 부르는 흐름, 쿠버네티스라면 컨트롤 플레인 전체가 배포 한 건을 처리하는 흐름. 핸드셰이크 메시지가 세션 키가 되는 과정, 인가 코드가 토큰으로 바뀌는 상태 전이, 스케줄러 하나의 필터·점수 알고리즘은 이 스킬이 아니다.

## 고정 규칙 (어기면 이 스킬이 아니다)

1. **3겹 설명** — 겹 1 자막·말풍선(늘 보임) → 겹 2 더 보기 패널(하는 일·누구와 무엇으로·내부 순서·흔한 오해) → 겹 3 실제로는?(그 순간의 실제 요청·저장 기록·명령 출력). 패널을 여는 동안 사건은 멈춘다.
2. **비유와 실제가 다른 곳은 말로 밝힌다** — 예: "크레인이 상자를 옮기지만 실제로는 장부에 `nodeName` 한 줄을 적을 뿐". 자막이나 패널에 반드시 한 번.
3. **이름 색** — 파랑 공식 용어 · 노랑 직접 지은 이름 · 회색 자동 생성. 엔진이 `content.js` 의 `names` 규칙으로 자동으로 칠한다. 색 글자에 마우스를 올리면 이유가 뜬다. → `references/naming-colors.md`
4. **예시 이름은 직접 지은 티가 나게** — `web`, `app`, `test` 처럼 공식 용어로 오해할 이름 대신 `my-shop` 같은 이름. 한 번 정한 이름은 모든 블록(명령·출력·로그)에서 같게 쓴다. 공식 이름이 없는 역할에는 하이픈 붙인 공식처럼 보이는 이름(`TLS-termination`)을 지어내지 않고 평범한 말로 쓴다.
5. **실제로는? 은 진짜 형식, 진짜 사실** — 실제 명령, 실제 API 경로, 실제 로그·이벤트 형식. 값은 단순화해도 형식은 지어내지 않는다. 실존하는 인증기관·인증서 체인·버전 번호는 확인한 것만 쓰고, 못 확인했으면 `Example CA` 처럼 가짜임이 분명한 이름을 쓴다. 다 쓴 뒤 블록 사이 경로·숫자·이름이 맞는지 점검한다 → `references/content-layers.md`
6. **원본 자료의 오류는 고친다** — 받은 이미지·자료에 틀린 연결·빠진 단계가 있으면 바로잡고, 보고에 무엇을 고쳤는지 쓴다.
7. **엔진 파일은 주제마다 고치지 않는다** — `index.html · style.css · iso.js · engine.js` 와 벤더링한 `gsap.min.js · MotionPathPlugin.min.js` 는 공용이다. 주제는 `world.js · content.js · world.css` 세 파일로만 만든다. 엔진에 기능이 필요하면 스킬의 `engine/` 을 고치고 `--engine-only` 로 갱신한다.

## 범위

**데스크톱 브라우저 전용이다.** 모바일·태블릿·터치 조작은 만들지도 검사하지도 않는다. 기준 화면은 가로 1000px 이상(넓은 창과 세로가 짧은 창 두 크기로 잰다).

## 자유로운 것

세계관, 그림체·색, 장면 수(5~8 권장), 어떤 물체가 어떻게 움직일지, 카메라 위치, 배경 움직임.

## 진행

### 0. 폴더 만들기

출력 폴더는 사용자·프로젝트가 정한다. 정해진 곳이 없으면 묻는다. 아래 `<스킬>` 은 이 SKILL.md 가 있는 폴더다.

```bash
node <스킬>/scripts/new_world.mjs <폴더>                 # 최소 템플릿에서 시작
node <스킬>/scripts/new_world.mjs <폴더> --engine-only   # 기존 지도의 엔진만 최신으로
```

GSAP(3.13.0)은 엔진 폴더에 들어 있어 오프라인에서도 동작한다. 글꼴(Pretendard)만 CDN 에서 받고, 못 받으면 시스템 글꼴로 떨어진다. 폴더째 배포하면 그대로 동작한다.

### 1. 재료 읽기 — 대화로 정리한다

받은 이미지·자료·주제에서 세 가지를 뽑는다.
- **부품**: 무엇이 있나 (역할 한 줄씩)
- **관계**: 누가 누구와 **어떤 방식으로**(프로토콜·호출) 무엇을 주고받나
- **흐름**: 대표 사건 2~4개 (예: 배포하기, 요청 보내기, 하나 늘리기, 하나 죽이기)

원본의 오류·누락도 이때 표시한다.

### 2. 짧게 합의하고 시제품부터

한 번에 묻는다: **세계관 제안 1개(이유 한 줄)** · **첫 사건 1개** · 범위. 사용자가 "알아서"라고 하면 바로 진행한다.
처음에는 **지도 + 사건 하나**만 만들어 보여 주고, 그림체·속도·정보량을 고친 뒤 사건을 늘린다.
세계관 고르는 법 → `references/world-design.md`

### 3. 대응표 — 비유 ↔ 실제

부품마다 `비유 이름 · 실제 이름 · 지도에서의 모습 · 비유가 실제와 다른 점`. 이 표가 `content.js` 의 `actors` 와 `world.js` 의 라벨이 된다.
**기록하는 곳**과 **실행하는 곳**이 지도에서 다른 장소로 보여야 한다.

### 4. 사건을 장면으로

사건 하나 = 장면 5~8개. 장면마다 한 줄씩 적는다:
`주인공 부품 · 움직임 하나 · 카메라가 볼 곳 · 무엇이 어디로 움직이나 · 자막(두 문장)`.
"이 장면이 끝나면 무엇이 달라져 있나"에 답이 없으면 앞뒤 장면과 합친다.

- **한 장면 = 주인공 하나 + 움직임 하나.** 신분증 확인과 봉인 완료처럼 이야기가 둘이면 장면을 쪼갠다.
- **움직이는 것은 이름을 부른다.** 봉투·불빛·선 색 전환처럼 화면에서 움직이거나 바뀌는 것은 그 장면의 자막이나 말풍선 글에 이름이 나와야 한다. 화면에만 있고 글에는 없는 동작은 못 알아본다.
- **앞 사건이 남긴 상태를 밝힌다.** 캐시·HSTS·쿠키·이미 배포된 앱처럼 사건이 남기는 상태가 있으면, 다음 사건의 **첫 자막**에서 "처음 방문(기록 없음)에서 시작"인지 "앞 사건에 이어서"인지 쓴다. 앞 사건의 응답이 남긴 상태로는 불가능한 일(HSTS 를 받은 브라우저가 http 로 나가기)을 보여 주지 않는다.
- **엔진 UI 가 차지하는 자리를 비운다** — 왼쪽 아래 사건 패널, 아래 자막, 열리면 오른쪽 440px 패널. 중요한 물체를 거기 두지 않는다 → `references/world-design.md`
소통은 흐르는 점선(`api.showLink`)으로 보여 준다. **"모두 장부를 지켜본다"** 같은 구조는 선으로 드러나야 한다.

### 5. content.js — 설명 내용

`actors` (부품별 3겹 내용) · `events` (사건별 장면 자막과 실제로는?) · `names` (이름 색 규칙).
**`real` 의 첫 단어만** 자막 칩에 보인다("Web Browser" → "Web"). 첫 단어가 그 부품을 대표하게 쓴다.
분량·형식 → `references/content-layers.md` · 이름 규칙 → `references/naming-colors.md`

### 6. world.js — 지도와 움직임

`build`(한 번 그리기) · `ambient`(배경 움직임) · `reset`(기준 상태) · `scenes`(사건별 장면 함수).
엔진 API·좌표계 → `references/engine-api.md` · 함정 → `references/pitfalls.md` (**쓰기 전에 읽는다**)

### 7. 검증 — 코드 먼저, 그다음 눈

```bash
node <스킬>/scripts/check_world.mjs <폴더>
```

통과할 때까지 브라우저를 열지 않는다. 그다음 로컬 서버로 열고(`python3 -m http.server <포트>`) 장면마다 확인한다.
**브라우저 자동화의 함정(백그라운드 탭에서 멈춘 애니메이션 · 같은 포트의 캐시 · 45초 제한)은 `references/pitfalls.md` 확인 절에 있다 — 열기 전에 읽는다.** 자동화 탭에서는 아래를 먼저 실행한다(파일에는 넣지 않는다).

```js
gsap.ticker.lagSmoothing(0); setInterval(() => gsap.ticker.tick(), 16);
document.getElementById("introGo").click();
EXPLORER.startEvent("<사건 id>");  EXPLORER.goBeat(<장면 번호 0부터>);  EXPLORER.state();
```

**검토 질문**(코드 검사가 못 잡는 것 — 내용을 다 쓴 뒤 한 번 훑는다, `references/content-layers.md` 일치 점검 ①~⑧):
- 같은 이름·경로·숫자가 모든 블록에서 같은가? 에러 메시지의 개수(`0/N nodes`)가 다른 블록의 목록과 맞는가?
- 한 부품의 `talks`·`steps`·장면 설명·`xray` 가 **같은 호출 경로**를 말하는가? (kubelet → 런타임 → CNI)
- **자막의 전제**("처음 방문", "기록 없음")와 같은 장면 `xray` 의 값(쿠키·캐시·세션)이 맞는가? 사건 안에서도, 사건 사이에서도.
- hex·길이 덤프는 프로토콜 **버전 바이트**·오프셋·길이를 서로 계산했는가, 못 맞추면 `…` 로 줄였는가? 여러 종류 `kubectl get` 은 종류별 표인가?
- **고친 줄 주변의 숫자·전제를 다시 계산했는가?** (수정이 새 모순을 만든 사례가 많다)

검토까지 끝나면 `scripts/verify_browser.js` 를 페이지에서 실행해 `await EWV.all()` 로 rubric B 를 잰다 — 장면마다 끝 상태로 바로 넘겨 재므로 몇 초면 끝난다.
B 는 **넓은 창 + 세로가 짧은 창, 두 크기 이상**에서 잰다(`await EWV.at(1120, 700)` 처럼 같은 페이지를 iframe 으로 열어 잴 수 있다). 결과의 `viewport` 를 보고에 적고, 한 크기만 잴 수 있었으면 그 사실을 적는다 → `references/rubric.md`.
B8(라벨이 말풍선 글자를 가림)은 실패, B9(말풍선 꼬리가 주인공 근처를 안 가리킴)는 경고다.
B 가 통과하면 장면 몇 개를 실제 속도로 재생해 스크린샷으로 눈으로 본다(장면 단위로 나눠서). 평가 기준 전체 → `references/rubric.md`

### 8. 보고

경로, 만든 사건과 장면 수, 원본에서 고친 것, 확인한 것(장면별·브라우저)과 **확인하지 못한 것**(예: 실제 속도 재생을 못 본 장면)을 쓴다. 확인하지 않은 동작을 된다고 쓰지 않는다.

## 파일 지도

| 파일 | 내용 |
|---|---|
