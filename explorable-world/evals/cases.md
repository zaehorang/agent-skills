# 스킬 테스트 케이스

스킬이 **이 스킬의 문서만으로** 좋은 지도를 만드는지 본다. 만드는 쪽과 평가하는 쪽은 이 스킬을 만든 대화를 모르는 새 에이전트여야 한다(아는 사람은 문서의 빈틈을 기억으로 메운다).

## 진행

1. **만드는 에이전트** — 아래 요청문만 받는다. `<스킬>/SKILL.md` 를 읽고 그대로 따른다. 사용자에게 묻는 단계(2단계 합의)는 "알아서 판단"으로 대신하고, 무엇을 정했는지 기록한다. 끝나면 **막힌 곳·문서가 모호했던 곳**을 목록으로 남긴다.
2. **평가하는 에이전트** — 결과 폴더와 `references/rubric.md` 만 받는다. A → B → C 를 적용하고 보고 형식대로 `evals/results/<날짜>-<케이스>.md` 에 쓴다. 같은 방식으로 `examples/k8s-harbor` 도 채점해 기준점과 비교한다.
3. 두 보고를 합쳐 SKILL.md·references·엔진에 고칠 것을 정한다.

## 케이스

### http-https — HTTP 와 HTTPS 요청이 서버에 닿기까지

- 출력 폴더: 작업 중인 프로젝트 안의 새 폴더 (예: `explainers/http-https/`)
- 요청문:
  > 브라우저 주소창에 https://my-shop.example.com 을 입력했을 때 요청이 서버에 닿고 응답이 돌아오기까지의 흐름(DNS 조회 → TCP 연결 → TLS 핸드셰이크 → HTTP 요청·응답)을, HTTP 와 HTTPS 의 차이가 보이게 탐험하며 이해할 수 있는 페이지로 만들어줘. 세계관과 범위는 알아서 판단해.
- 보고 싶은 것:
  - 세계관이 "기록하는 곳 vs 실행하는 곳" 대신 이 주제에 맞는 구조(이름 찾기 · 연결 · 봉인 · 배달)를 장소로 나누는가
  - HTTP(봉인 없음)와 HTTPS(봉인)의 차이를 같은 지도에서 비교할 수 있는가
  - 비유가 어긋나는 곳(인증서 = 신분증 비유의 한계, 키 교환은 실제로 비밀을 보내지 않음 등)을 밝히는가
  - 실제로는? 에 실제 형식(`dig`, `curl -v`, TLS ClientHello/ServerHello, HTTP 요청·응답 헤더)이 나오는가
  - 예시 이름(`my-shop.example.com`)이 노랑, 프로토콜·헤더 이름이 파랑인가
  - **학습자가 정하지 않고 외부(호스팅 업체·DHCP·시스템)가 정한 값**(서버 공인 IP, 내 IP, 임시 포트, seq, DNS id, 세션 값)이 회색인가 — `references/naming-colors.md` 의 "누가 골랐나" 기준과 같다
  - 사건 사이 상태(앞 사건이 남긴 HSTS·캐시)를 다음 사건 첫 자막에서 밝히는가, 실존 인증기관·체인이 맞거나 가짜임이 분명한가
