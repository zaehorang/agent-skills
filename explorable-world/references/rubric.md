# 평가 rubric — 만든 지도가 "잘 만들어졌는가"

세 겹으로 본다. **A·B 는 기계가 판정하고, C 는 사람이나 모델이 판정한다.** A → B → C 순서로, 앞 겹을 통과해야 다음으로 간다.

## A. 정적 검사 — 통과/실패

```bash
node <스킬>/scripts/check_world.mjs <폴더>
```

`FAIL` 이 0건이어야 한다. `?` 경고는 보고에 옮겨 적는다.

## B. 브라우저 자동 검사 — 숫자로 판정

1. 폴더를 로컬 서버로 연다. **포트를 바꿔 가며 연다** — 같은 포트로 다시 열면 브라우저가 예전 `world.js` 를 캐시에서 읽는다.
   스킬 폴더 밖이면 그 폴더에서 `python3 -m http.server <새 포트>`.
2. 콘솔 에러를 자동화 도구로 읽는다(페이지를 연 직후 에러는 아래 스크립트가 못 잡는다).
3. `scripts/verify_browser.js` 내용을 페이지에서 실행하고 `await EWV.all()` 결과의 `summary` 를 본다.
   지도 폴더를 서버 루트로 열었다면 스크립트는 같은 서버에 없다 — `<스킬>/scripts/verify_browser.js` 파일을 읽어 그 **내용 전체를 JS 실행에 붙여 넣고**, 같은 호출 끝에 `await EWV.all()` 을 둔다.
   (파일 경로로 못 읽으면 `python3 -m http.server` 로 스킬 `scripts/` 를 CORS 헤더 붙여 다른 포트에 열고 `fetch('http://127.0.0.1:<포트>/verify_browser.js')` 로 가져와도 된다.)
   스킬 폴더를 서버 루트로 열었다면(예시 채점): `(0,eval)(await (await fetch('/scripts/verify_browser.js')).text()); await EWV.all()`

| 항목 | 뜻 | 통과 기준 |
|---|---|---|
| B1 `errors` | 검사 중 JS 에러 | 0 (+ 2단계 콘솔 에러 0) |
| B2 `heroHidden` | 장면 주인공이 화면 밖이거나 자막에 가린 장면 | 없음 |
| B3 `bubbleOut` | 말풍선이 화면 밖으로 나간 장면 | 없음 · `bubbleUnderCaption` 은 경고 |
| B4 `replayMismatch` | 차례로 넘긴 상태 ≠ 점으로 바로 간 상태 | 없음 |
| B5 `panelIncomplete` | 하는 일·소통·순서·실제로는? 중 빠진 패널 | 없음 |
| B6 `labelMinPx` | 전체 보기에서 가장 작은 라벨 글자 | 11 이상 (12 미만은 경고) |
| B7 `labelCovers` | 라벨이 클릭 물체를 35% 넘게 가림 | 경고만 |
| B8 `labelOverBubble` | 말풍선보다 위에 그려지는 라벨이 보이는 말풍선 글자를 10% 넘게 덮은 장면 | 없음 (현재 엔진은 말풍선이 라벨 위라 정상이면 항상 비어 있다. 층 순서가 바뀌었는지 보는 안전장치) |
| B9 `tailAwayFromHero` | 말풍선 꼬리 끝이 장면 주인공(확장 bbox, 주인공 크기의 30% · 14~50px 여유) 근처가 아닌 곳을 가리키는 장면. 어느 부품을 가리키는지(`→office`)를 함께 적는다 | 경고만 — 주인공이 아닌 상대가 말하는 말풍선이면 의도한 것일 수 있다. 엉뚱한 물체(80번 문 대신 443번 문이어야 하는데)면 고친다 |

`summary.pass` 가 true 여야 C 로 간다 (B1~B6 · B8 이 통과 조건. B7·B9 는 경고).

### 화면 크기 — 두 크기 이상에서 잰다

무대가 화면을 꽉 채우는 방식(`slice`)이라 창 비율에 따라 라벨 크기·잘리는 곳이 달라진다. 같은 지도가 1120x706 에서 pass, 763x819 에서 fail 이었고, 기준 지도는 1078x949 에서 pass, 1120x699 에서 B6 10.0px 로 fail 이었다. 그래서:

1. **넓은 창(가로 ≥ 1000, 예: 1280x720 이상) 과 세로가 짧은 창(세로 < 760, 예: 1120x700) 을 함께** 잰다. 결과의 `summary.viewport` · `sizeKind`(`wide/short` 등)를 보고에 적는다.
2. 창 크기를 못 바꾸면 `await EWV.at(1120, 700)` 처럼 같은 페이지를 그 크기 iframe 에 열어 같은 검사를 돌린다(결과에 `inFrame:true`). 이것도 못 하면 **한 크기만 쟀다는 사실과 그 크기를 보고에 쓴다** — "pass" 만 쓰고 크기를 빼지 않는다.
3. 크기마다 `summary` 를 따로 적는다. 하나라도 `pass:false` 면 그 크기를 적고 실패로 본다(그 크기가 기준 화면 밖이면 사유를 적고 경고로 낮출 수 있다).
기준 화면은 가로 1000px 이상 데스크톱이다. 모바일·태블릿은 범위 밖이라 재지 않는다.

## C. 품질 — 항목마다 0·1·2점

지도를 직접 보고 사건을 끝까지 따라간 뒤 매긴다. 근거(어느 장면·어느 패널)를 한 줄씩 남긴다.

| # | 항목 | 2점 | 1점 | 0점 |
|---|---|---|---|---|
| C1 | **겹 1만으로 이해** | 자막만 읽고 사건 흐름을 처음부터 끝까지 말할 수 있다 | 흐름은 보이나 빠진 고리가 있다 | 패널을 열어야 무슨 일인지 안다 |
| C2 | **정확성** | 실제로는? 이 실제 형식(명령·API·로그)이고 틀린 사실이 없다. 원본 오류를 고쳤다 | 사소한 부정확 1~2개 | 틀린 동작 설명이나 지어낸 형식 |
| C3 | **비유 품질** | 기록하는 곳과 실행하는 곳이 장소로 나뉘고, 비유가 어긋나는 곳을 밝혔다 | 구조는 보이나 어긋남을 밝히지 않았다 | 비유가 구조를 가리거나 오해시킨다 |
| C4 | **움직임이 정보** | 움직임이 "무엇이 어디로·누가 누구에게"를 보여 준다. 한 장면에 이야기 하나 | 일부 장면은 장식이거나, **서로 다른 부품이 서로 다른 일을 동시에** 한다 | 움직임이 흐름과 무관하다 |

C4 판정 기준 — **허용**: 같은 일을 여러 곳에서 동시에(부두 두 곳이 같이 이미지를 받음, 세 Pod 가 같이 생김 — 병렬이 곧 정보). **감점**: 서로 다른 부품이 서로 다른 일을 한 장면에서 동시에(반장의 watch 선 + 저장소선의 이미지 이동 + 상자 채색 + IP 태그가 한꺼번에, 신분증 확인 말풍선 + 발급소 점선 + 봉인 선 전환이 한꺼번에), 자막이 부른 부품이 3개 이상인 장면. 한 장면 = 주인공 하나 + 움직임 하나. 둘 이상이면 1점.
| C5 | **소통 구조** | 누가 누구를 지켜보고·부르는지가 선으로 보이고, 핵심 구조(예: 모두 한 곳을 거친다)가 드러난다 | 선은 있으나 구조가 안 읽힌다 | 소통이 안 보인다 |
| C6 | **이름 색** | 파랑·노랑·회색 분류가 맞고, 예시 이름이 직접 지은 티가 난다 | 오분류 1~2개 또는 예시 이름이 애매 | 분류가 자주 틀리거나 색 규칙이 깨진다 |
| C7 | **탐험성** | 주요 부품을 모두 누를 수 있고, 말풍선 → 패널 → 실제로는? 이 자연스럽게 깊어진다 | 일부 부품이 빠졌거나 깊이가 고르지 않다 | 처음부터 정보가 쏟아지거나 깊이 들어갈 곳이 없다 |

**합격: 14점 중 11점 이상, 0점 항목 없음.**
