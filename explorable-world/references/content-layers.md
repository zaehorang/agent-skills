# 3겹 설명 쓰는 법 (content.js)

보는 사람은 대부분 **겹 1에서 멈춘다.** 겹 1만 읽어도 흐름이 이해돼야 하고, 겹 2·3은 궁금한 사람을 위한 것이다.

## 형식

```js
var ACTORS = {
  crane:{ name:"크레인 배치원",            // 비유 이름 (지도 라벨과 같게)
    real:"kube-scheduler",                 // 실제 이름 — 문자열. 자막 칩에는 첫 단어만 보인다
    tip:"…",                               // 겹 1 말풍선 — 한 문장
    what:"…",                              // 겹 2 — 하는 일 2~3문장, 핵심에 <b>
    talks:[["관제탑 접수 창구","HTTPS watch","자리 미정 감시 · 배치 결과 기록"]],  // [상대, 방식, 주고받는 것]
    steps:["…","…"],                       // 겹 2 — 안에서 일어나는 순서 3~7개
    xr:[{l:"배치 결과", code:"<span class='k'>$ kubectl get pod -o wide</span>\n…"}],  // 겹 3 — 언제든 확인할 수 있는 것
    myth:"…? — …" },                       // 흔한 오해 한 줄
};
var DEPLOY_BEATS = [
  { actor:"crane",                         // 이 장면의 주인공 (패널 '지금 이 순간'이 여기에 붙는다)
    text:"…",                              // 겹 1 자막 — 두 문장
    xray:[{l:"…", code:"…"}] },            // 겹 3 — 바로 이 순간의 실제 요청·기록·출력
];
window.CONTENT = { title, subtitle, logo, intro:{title, body, sub}, actors:ACTORS,
  events:[{id:"deploy", icon:"📦", title:"앱 배포하기", sub:"…", beats:DEPLOY_BEATS},
          {id:"scale", icon:"➕", title:"…", ready:false, beats:[]}],   // 준비 중 사건
  names:{…},
  lang:"ko", ui:{…} };   // 선택 — 엔진 화면 글자를 다른 언어로 (engine-api.md '화면 글자 바꾸기')
```

**키 이름을 겹치게 쓰지 않는다.** 한 객체에 `real:` 이 두 번 나오면 뒤의 것이 앞을 조용히 덮는다(실제로 겪음 — 실제 이름이 목록으로 바뀌어 화면이 깨졌다). 실제 이름은 `real`, 겹 3 목록은 `xr`.

## 분량

| 칸 | 분량 | 쓰는 법 |
|---|---|---|
| `tip` | 한 문장 ≤ 80자 | "무엇을 하는 곳/사람"만. 비유 세계의 말로 |
| `beat.text` | 두 문장 ≤ 150자 | 첫 문장: 무슨 일이 일어나나. 둘째: 왜 중요한가·비유와 실제의 차이 |
| `what` | 2~3문장 | 실제 동작. 공식 용어는 괄호로 병기 — "지켜보다가(watch)" |
| `talks` | 1~3줄 | 방식은 실제 프로토콜·호출 이름 (`HTTPS watch`, `gRPC`, `CRI`) |
| `steps` | 3~7개 | 동사로 끝나는 짧은 구. 공식 용어를 괄호로 |
| `xr` / `xray` | 1~3블록 | 실제 명령·API·로그 형식. `<span class='k'>` 명령줄, `<span class='g'>` 성공, `<span class='c'>` 주석, `<span class='y'>` 굵게 강조 |
| `myth` | 한 줄 | "○○한다? — 아니다, △△" 형식 |

**자막 칩은 `real` 의 첫 단어만 보여 준다** (`String(real).split(" ")[0]`). "Web Browser" 는 "Web", "Certificate Authority" 는 "Certificate" 로 뜬다. 첫 단어가 그 부품을 대표하고 다른 부품과 겹치지 않게 쓴다(`TCP:443 (HTTPS 포트)`, `CA (Certificate Authority)`). `kube-apiserver` 처럼 한 단어인 이름은 문제없다.
**공식 이름이 없는 역할**(엿보는 사람, TLS 를 풀어 주는 지점)은 `TLS-termination`, `On-path-observer` 처럼 하이픈으로 붙여 공식 식별자처럼 보이게 만들지 말고 `TLS termination (nginx ssl)`, `on-path observer` 처럼 평범한 말로 쓴다.

## 자막 쓰는 요령

- **주어는 비유 이름**, 공식 용어는 처음 나올 때 괄호로: "순찰 로봇은 늘 장부를 **지켜보고(watch)** 있어요."
- `<b>` 는 한 문장에 하나 정도. 강조는 흰 굵은 글씨로 보인다(노랑·파랑은 이름 색 전용).
- **움직이는 것은 이름을 부른다** — 그 장면에서 움직이거나 바뀌는 것(봉투, 불빛, 선 색)은 자막이나 말풍선 글에 이름이 있어야 한다. 한 장면 = 주인공 하나 + 움직임 하나.
- **앞 사건이 남긴 상태를 첫 자막에서 밝힌다** — 사건이 캐시·HSTS·쿠키·배포된 앱 같은 상태를 남기면, 다음 사건 첫 자막에 "기록 없는 새 상태에서 시작" 또는 "앞 사건에 이어서"를 쓴다. 앞 사건의 겹 3(`xray`)이 남긴 상태와 다음 사건의 전제가 어긋나지 않는지 본다.
- 마지막 장면 자막은 **사건 전체의 깨달음**으로: "누구도 서로에게 직접 지시하지 않았어요 — 모두 장부를 보고 자기 몫만 했어요."
- 비유와 실제가 어긋나는 장면에서는 자막에 직접 밝힌다.

## 겹 3 '실제로는?' 쓰는 요령

- **지금 이 순간(`xray`)** 과 **언제든(`xr`)** 을 나눈다. 패널을 열었을 때 장면의 주인공이면 둘 다 보인다.
- 한 블록 = 한 가지. 제목(`l`)은 "무엇을 보는가" ("실제로 나간 HTTP 요청", "장부에 생긴 키").
- 예시 이름이 직접 지은 이름임을 드러내는 YAML 주석을 한 번은 둔다: `name: my-shop   # ← 직접 지은 이름`.
- 실패 모습(에러 이벤트·거부 응답)을 한 블록 넣으면 이해가 깊어진다.

## 겹 3 사실 규율 — "실제로는?" 은 진짜여야 한다

- **실존하는 것은 확인한다** — 인증기관·중간 인증서·루트·체인 순서·프로토콜 버전·포트·기본값은 공식 문서나 실제 출력으로 확인한 것만 쓴다. 확인하지 못했으면 `Example CA`, `example.com`, 문서용 IP 대역(`203.0.113.0/24`) 처럼 **가짜임이 분명한 이름**을 쓴다. (사례: Let's Encrypt `E5` 중간 인증서의 발급자를 `ISRG Root X1` 로 적음 — `E5` 는 `ISRG Root X2` 아래다.)
- **도구가 실제로 찍는 모양으로** — `tcpdump` 는 `-S` 없이는 상대 번호(`ack 1`)를, `kubectl get -w` 는 열 정렬된 표를, watch API 는 `GET …?watch=true` 응답의 `{"type":"ADDED","object":…}` 줄을 낸다. `WATCH … → ADDED` 같은 한 줄 요약을 형식처럼 쓰지 않는다.
- **여러 종류를 한꺼번에 조회하면 종류별 표** — `kubectl get deploy,rs,pod` 는 한 표가 아니라 종류마다 **헤더가 있는 표**(`NAME READY UP-TO-DATE AVAILABLE AGE` / `NAME DESIRED CURRENT READY AGE` / `NAME READY STATUS RESTARTS AGE`)를 빈 줄로 나눠 찍고 이름 앞에 `deployment.apps/`·`replicaset.apps/`·`pod/` 가 붙는다. "3 desired · 3 ready" 같은 요약 줄을 만들지 않는다.
- **바이트 덤프(hex·length)는 계산해서 맞추거나 `…` 로 줄인다** — 덤프를 넣으면 버전 바이트(TLS 1.3 레코드 헤더는 `17 03 03`), 헤더 길이로 정해지는 오프셋(IP 20 + TCP 20 바이트 뒤 0x0028 부터 TCP 옵션이 아니라 페이로드), 패킷 `length`·IP total length·말풍선에 쓴 바이트 수를 **서로 계산해** 일치시킨다. 못 맞추겠으면 그 줄을 `…` 로 생략하고 숫자를 빼는 편이 낫다. 겉보기 형식이 진짜여도 숫자가 안 맞으면 틀린 것이다.
- **블록 사이 일치 점검** — 겹 3 을 다 쓴 뒤 훑는다: ① 같은 대상의 이름이 모든 블록에서 같은가(`kubectl get deploy my-shop` 의 `NAME` 이 `my-shop`) ② 경로·번호가 서로 맞는가(발급한 경로 = 서버 설정이 읽는 경로, IP 와 DNS 답) ③ 앞 블록의 값이 뒤 블록에서 그대로 나오는가 ④ 사건 사이 전제(위 "앞 사건이 남긴 상태")가 맞는가 ⑤ **에러 메시지의 개수가 다른 블록의 목록과 맞는가** — `0/3 nodes are available` 이면 `kubectl get nodes` 가 3줄, 거절 사유의 합(`1 node(s) had untolerated taint…, 2 Insufficient memory`)도 3 ⑥ **한 부품의 `talks`·`steps`·장면 설명·`xray` 가 같은 호출 경로를 말하는가** — kubelet → 런타임(CRI) → CNI 인데 `talks` 에 kubelet ↔ CNI 를 직접 적으면 틀리다 ⑦ **자막의 전제 ↔ 같은 장면 `xray` 의 값** — 자막이 "처음 방문"·"기록 없음"이면 같은 장면 `xray` 에 쿠키·캐시·세션처럼 이전 방문을 전제하는 값이 없어야 한다(사건 사이뿐 아니라 **사건 안**에서도). 쿠키를 보여야 하면 "이전 방문의 쿠키는 남아 있다"처럼 전제를 고친다 ⑧ 이벤트·로그 문구가 한 형식인가(`Created container my-shop` 과 `Started container my-shop`, 콜론 유무를 섞지 않는다).
- **고친 뒤에는 고친 줄 주변을 다시 계산한다** — 수정이 새 오류를 만든 사례: 전제를 "처음 방문"으로 바꾸고 뒤 장면의 `Cookie: sid=…` 는 그대로 둠 / hex 덤프를 IP 헤더부터 시작하게 고치고 오프셋·버전 바이트는 그대로 둠 / `0/2` 를 `0/3` 으로 고치지 않고 노드 목록만 늘림. 한 줄을 고치면 그 줄의 숫자·이름·전제와 같은 값이 나오는 다른 블록을 다시 훑는다. `check_world.mjs` 가 이름 하나는 자동으로 잡는다(규칙에 안 걸리는 이름 토큰).
